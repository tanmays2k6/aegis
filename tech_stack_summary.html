End-to-End Cryptographic Ingestion Flow
1
Client Capture & Fingerprinting: Officer selects evidence file. Browser Web Crypto API computes SHA-256 in memory before network transmission.
2
Gateway Interception & Verification: Express 5 API intercepts request, verifies user JWT and role via auth.js, and recomputes SHA-256 via Node crypto to guarantee zero transit tampering.
3
Blockchain Ledger Anchoring: PostgreSQL/Supabase acquires an advisory transaction lock, anchors the file into evidence and evidence_versions, links previous block hash, and appends to hash_chain.
4
Immutable Audit Chaining: Event is recorded to audit_log using append_audit_entry, mathematically binding officer identity, timestamp, and action to the historical audit chain.
1. Client Trust
React 18 + Web Crypto ensures that an immutable SHA-256 fingerprint is generated at the moment of intake on the field officer's terminal.
2. Gateway Security
Express 5 + RBAC Middleware acts as a security firewall, enforcing role permissions, file limits (10MB), and dual server-side hash verification.
3. Ledger Immutability
PostgreSQL + pgcrypto executes sequential block linking with advisory transaction locks, achieving zero-gas blockchain integrity in SQL.

2. Backend & Middleware Layer

Node.js (ES Modules Environment) Server Runtime
Industry Standard Usage
Asynchronous event-driven server runtime. Modern projects configure "type": "module" to use native import/export syntax.
Implementation in AEGIS
Runs the entire backend architecture asynchronously with non-blocking I/O, streaming base64 buffers, and interacting with PostgreSQL via RESTful connections.
Design Rationale
Allows a unified JavaScript/ESM ecosystem across frontend and backend, avoiding mental overhead and enabling shared models and cryptographic validation logic.
Express.js 5 REST API Framework
Industry Standard Usage
Minimalist web framework providing routing, body parsing, and middleware chaining.
Implementation in AEGIS
Entrypoint at backend/server.js. Routes requests into structured MVC layers:
• /api/auth → User registration, login, and profile fetching.
• /api/cases → Case registry (FIR creation, status updates).
• /api/evidence → Evidence anchoring, status changes (draft/submitted/approved/locked).
• /api/audit → Immutable audit trail queries (restricted to auditors/admins).
• /api/compliance → System assurance metrics and health check.
Configured with express.json({ limit: '30mb' }) to handle base64-encoded evidence files.
Design Rationale
Application Firewall: Never exposes the database directly to clients. The Express layer intercepts requests to enforce size quotas, perform cryptographic checks, and audit actions before database commits.
Node.js Native crypto Module Dual-Hashing Engine
Industry Standard Usage
Native C++ OpenSSL binding in Node.js for high-speed cryptographic operations.
Implementation in AEGIS
In backend/controllers/evidenceController.js: 
const bytes = Buffer.from(fileContent, 'base64');
const actualHash = crypto.createHash('sha256').update(bytes).digest('hex');
if (actualHash !== currentHash) {
  return res.status(400).json({ error: 'Evidence hash does not match uploaded file.' });
}
Design Rationale
Dual-Verification Integrity: Guarantees that if a single bit of the file was corrupted or tampered with over the network, the upload is rejected immediately.
Custom Auth & Role-Based Access Control (RBAC) Security Middleware
Industry Standard Usage
Middleware protecting private endpoints by validating JWT headers and checking user authorization levels.
Implementation in AEGIS
In backend/middleware/auth.js:
• requireAuth: Extracts Bearer <token>, queries Supabase Auth, and resolves profile data (full name, role, jurisdiction).
• requireRoles(...roles): Reusable guard (e.g. requireRoles('admin', 'auditor')) returning HTTP 403 Forbidden on unauthorized access attempts.
Design Rationale
Enforces judicial authority hierarchy: Investigating Officers upload evidence; Court Clerks review and approve for court admissibility; Auditors verify chain integrity without editing records.

3. Database & Blockchain Ledger Layer

Supabase (Enterprise PostgreSQL 15+) Relational Database & Auth
Industry Standard Usage
Open-source Firebase alternative providing managed PostgreSQL, automated REST endpoints, and JWT authentication.
Implementation in AEGIS
Stores structured relations across 6 core tables:
Table Primary Role Integrity Role
profiles User identities (officers, clerks, auditors) Foreign-key bound to Supabase auth.users
cases FIR case registry & jurisdictions Parent anchor for all subsequent evidence items
evidence Primary evidence item records Stores active SHA-256 fingerprint & legal status
evidence_versions Historical versions of modified files Maintains version-level hash chaining
audit_log Chronological log of every system action Chained cryptographically via previous_chain_hash
hash_chain Master blockchain ledger Global sequential ledger unifying evidence and audit logs
Design Rationale
Provides strict ACID transactions, foreign key integrity, and relational joins required for criminal justice proceedings.
PL/pgSQL Stored Procedures & pgcrypto Extension Blockchain Core
Industry Standard Usage
Compiled procedural code running inside the PostgreSQL database engine. pgcrypto enables cryptographic hashing (SHA-256) in SQL.
Implementation in AEGIS
Defined in backend/supabase/migrations/20260909000000_secure_api_and_chain.sql:
• Advisory Concurrency Lock: PERFORM pg_advisory_xact_lock(90226001); prevents race conditions and ensures strictly sequential ledger numbers.
• Master Blockchain Formula: 
v_ledger_hash := encode(extensions.digest(
  v_ledger_previous || ':evidence_version:' || v_version.id::text || ':' || v_version_hash,
  'sha256'
), 'hex');
• Chained Audit Logging (append_audit_entry): Every action calculates a new block hash linking the previous action's hash, officer UUID, action name, and UTC timestamp.
Design Rationale (Why Not Ethereum/Hyperledger?)
Zero-Gas, Instant Finality: Running the blockchain hash-chain directly inside PostgreSQL stored procedures delivers mathematical immutability and tamper-detection without expensive cryptocurrency gas fees, complex validator networks, or slow block times.
